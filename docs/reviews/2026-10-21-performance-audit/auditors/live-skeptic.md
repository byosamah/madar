# Skeptic verdicts: live (commit 1d45aae5, code read in deploy-test)

I re-read the cited code, re-read the raw JSON of the auditor (d-task.json for the save), checked the cache rules, and ran one curl on the test copy (LV-13).

LV-1 weakened (4 to 2). The preload and the cost are real. But the font files never change (the licence forbids it), so their hash stays the same on each release. The files are in /assets/ with an immutable one-year header (config/headers.template). So the 298 KB cost hits only a first visit on a device or a cleared cache, not "after a release". The aborted-font runs also never load the fonts at all, so the gain is an upper bound: the fonts still load after the first paint and share the pipe with the first API answers. Fix is a visible change (fallback font flash), the finding says so.

LV-2 weakened (5 to 3). Code holds. signals.ts: the channel echo of an own write sets mixed = true (line 296 path, origin channel), the own answer then flushes by microtask, and freshOf returns undefined, so every read that the signal names reloads. d-task.json shows 6 of 6 rounds with 3 batches (8 reads, then 3 reads and 5 reads again, starting 1 to 3 ms after the answer). But the second pass returns the same data, so no screen change and no wait. The cost is 2 extra Edge calls and about 8 KB gzip per save: about 3 to 4 percent of the 500,000 calls at 300 saves a day. Fix is safe only in this form: keep the ids of the channel signals that made mixed true, remove the ids that the own answer names, and keep mixed true for any gap (all, personAll), any empty-list signal, or any id that the own answer does not name.

LV-3 weakened (4 to 3). Code holds: signals.ts schedule() waits mergeMs 1000 for every non-own signal, and the header comment says it is the plan on purpose (a call saver). The 2.2 s chat figure is real. But the fix costs calls: a burst gets a leading pass and a trailing pass (2 batches instead of 1), and a chat talk is a burst. Safer form: shorten the window (about 150 ms) only when the signal names the kind messages and the person has the Inbox open. Behavior and data stay the same.

LV-4 weakened (4 to 2). Most of the "21 calls" are not fixable here: 13 are the idle tabs (the anonymous direct-chat office signal, the same as DF-2: needs a server change), 1 batch is the LV-2 duplicate, the receiver's markRead and the sender's typing are by design. The claimed cause is partly wrong. chats.send already calls markReadNow (handlers/chats.ts:389), so readUpTo equals the new message and `behind` is false. The own markRead comes from `seenBehind` (ConversationPane.tsx:214-219): the seen time does not move on send. Excluding the own newest message from seenBehind removes 1 batch (a write and 4 reads) for each message sent, about 60 batches a day. Small edge case: today a sender who sends while an older message from the other person is in flight marks it as seen too early; the fix makes that exact.

LV-5 weakened (3 to 2). Code holds (main.tsx:85-87, screens.ts:126). The prefetch is on purpose: the comment says a release that removes old chunks finds them already in memory. It runs at idle after the first render, only on a cold cache (hashed chunks stay cached), and the mobile first batch took 0.73 s from its POST against 0.84 s on desktop, so no sign that it slows the first answer. Dropping it also drops the release protection. Safe form: keep all screens but gate by navigator.connection.saveData and by the sign-in screens, and start the rare screens (Dashboard, Open Space, Admin) on pointerdown.

LV-6 weakened (3 to 2). The 3 preflights exist since 2026-10-08 (proof.md line 1256 and the 3 preflights noted in the Lighthouse record). The claim "3 of 10 Edge calls" is wrong: platform-facts.md line 110 quotes Supabase, OPTIONS requests are not billed. The 3 preflights run in parallel, so they cost one round trip. The forwarder fix was measured and removed (FET-10: not faster over a session). CORS_MAX_AGE is 7200 (Chrome cap). Only a new tab context and Safari (short cache, inferred) pay it.

LV-7 weakened (3 to 2). Code holds (main.tsx awaits loadWords before the first render, firstWords.ts starts at the entry script). BND-7 already moved the load to the first script. The remaining gain is the words fetch overlapping the script fetch: about 170 ms on a cold desktop load only. The Home meetings.list step is DF-6 (draws nothing on a day with no meeting). The fix needs a tiny extra script request and a CSP-safe link, so effort is more than S.

LV-8 weakened (3 to 2), fix not safe. Same issue as DF-3 of the dataflow audit. The join pass is the guard for a change saved between the first read and the subscription. The proposed rule "skip reads that ended a few seconds before" keeps that gap open, and the finding says behaviorChange true. Data does not change on screen (same answers, structural sharing). Cost: 3 Edge calls per cold load and per rejoin, about 1 to 2 percent of the quota. A safe form needs the server "changed since" call, which is a contract addition.

LV-9 weakened (3 to 2). createQueryClient sets staleTime Infinity and gcTime of one hour for every api read (runtime.tsx:53). So a screen the person has opened already shows from the cache at once. The 450 to 650 ms is the first open of each screen in a session. Pointerdown prefetch (as project rows do) is safe and saves only the press to release time, about 50 to 150 ms.

LV-10 confirmed (2). Code holds: MapCanvas is a lazy import in DashboardMap, ProjectPlace and PinPicker. Note that part of the 893 to 1,316 ms is the map start and the tile style, which a chunk prefetch does not remove. Safe fix: start the import on pointerdown or hover of the Map tab. Never add it to the idle prefetch (284 KB gzip).

LV-11 weakened (2 to 1). I found the cause with fontTools: the only glyph of the project page text and words that Thmanyah lacks is U+00B2 (the square in m2). That glyph falls to Inter Latin (74 KB). It loads once per device, then the browser keeps it. Fix: add U+00B2 to the Madar Digits subset (inter-digits-dot.woff2, an Inter file, so it may change). Check that the glyph looks the same as today.

LV-12 weakened (2 to 1). Overlaps DF-8. The owner already read the usage on 2026-10-21 and booked the month at about 45 percent of the 2 million with the presence parts in, and decided that cost step 4 does not apply (TASKS.md line 931). The 150,000 estimate is inside that. A fix shows the dots late (behavior change), and MentionField in the composers needs the same ids.

LV-13 weakened (1 to 1), fix not safe as written. Measured by curl: /assets/nothing-abc123.js returns 200 text/html with the immutable header, as claimed. But an old tab never asks for the same removed chunk URL again after the reload guard, and the browser keeps the bad copy only under a URL that no page uses. No real harm. A _redirects 404 rule or a 404.html can turn off the SPA fallback or break real assets: test on the preview copy first.
